# 本地邮件摘要模型

当前选择：Ollama 0.40.16 原生 macOS + `qwen3:4b-instruct-2507-q4_K_M`。
Web 后端继续使用 `.venv`，模型由独立进程运行，通过固定的本机 HTTP 地址调用，不新增 Python 模型框架依赖。

2026-11-12 本机验证：Metal / Apple M5，运行时显示 100% GPU、约 3.9 GB；同一批五封真实邮件在 v2 提示词下全部通过结构、原文行号与日期引用检查，平均每封 9.81 秒（已加载模型），范围 6.36–15.49 秒。本轮未触发正文字符截断。此结果不等于人工核对后的语义准确率，也不保证其他邮件或设备的速度。

当前提示词为 v4：面向用户输出自然对话式的一小段话，不把分析逻辑呈现为字段清单。
原批次同样三封邮件重测 3/3 通过，平均每封 8.00 秒；后端 41 项测试及格式、Lint 检查通过，未修改前端。

随后按用户授权测试最近 20 封不同的已收邮件（v4）：18 封通过，2 封因截止时间无法在对应引用中逐字核实而被拒绝，未作成功处理；成功项平均推理 7.36 秒，整批含邮箱读取耗时 154.36 秒，无正文字符截断。结果包含失败记录，不能将 90% 校验通过率解释为语义准确率。

2026-11-13 v4.1（提示词正文沿用 v4，仅把“最多180字”改为 150 字，与 160 字校验上限一致）：

## 启动

项目中已安装运行程序及模型后，在项目根目录打开一个终端：

```bash
bash scripts/ollama-serve.sh
```

保持终端运行，Ctrl+C 停止。服务只监听 `127.0.0.1:11434`，启用 `OLLAMA_NO_CLOUD=1`，不设置开机启动。若已有服务占用端口，脚本退出，不终止其他程序。
模型保存在 `private-data/models/ollama`，运行程序在 `.tools/ollama`；两者均被 Git 忽略。此服务不依赖 Web 服务启动，账号与收件箱仍可独立运行。

## 少量真实邮件测试

真实 Gmail 连接须已经由用户授权。只有明确获准处理真实邮件时才运行：

```bash
.venv/bin/python scripts/test-mail-summary.py --allow-real-mail
```

若有多个用户或邮箱，增加 `--username 账号`、`--connection-id 邮箱连接ID`，拒绝自动跨用户选择。脚本只处理所选邮箱最近指定数量的已收邮件，默认五封，包含已归档邮件，排除已发送、草稿、垃圾邮件和垃圾箱；不会改变已读状态。

控制台只打印序号、成功/失败和耗时。JSON 和便于阅读的 TXT 报告写入 `private-data/summary-tests/`，目录权限 700、文件权限 600，不提交 Git。报告含私人主题、发件人、摘要及少量原文引用，仅供本人本机查看；不存完整正文。可直接在 VS Code 中打开报告。

v4 提示词要求像助手向用户解释邮件一样，用连贯、简短的一段话自然交代消息主体、发信缘由、可选或必须的操作及明确期限。通常 40–100 字、硬上限 160 字，不编号、不分点、不写“发件人：”“目的：”等标签；不用“该邮件是”“旨在”等公文腔，不凑无操作/无期限的信息。可选事项用“可以”，明确要求才用“需要”。风格示例不作为邮件事实。TXT 只展示这段用户文案及必要的内容限制；JSON 内保留事实、待办、原文引用等内部核验数据，不再逐项拼成用户清单。校验会拒绝多行、编号和字段标签式概述。

邮件数据只作为用户消息输入，系统提示词在 `backend/app/mail_summary.py`；模型没有发送、删除、执行命令或浏览网页的工具。

输出必须通过 Pydantic JSON 校验。模型选择编号原文行，程序验证行号并直接回填重点/待办的引用，避免小模型改写引用；截止时间必须出现在对应引用中。未知期限不推算。不通过校验、生成截断、本地服务失败或超时会明确失败，不调用云模型补救。原文引用校验不能证明摘要语义正确，仍需人工对照邮件评估遗漏和误解。

测试数量可用 `--count 20` 指定（支持 1–20，默认 5）；处理真实邮件前须取得对应数量的用户授权。调整提示词后，可增加 `--replay-report private-data/summary-tests/报告文件.json --count 3` 重测原报告中的前三封邮件，脚本会再次检查报告中的账号与邮箱归属。

每封正文当前最多取前 10000 字符，超过时标注截断，附件仅提供文件名。上下文 16384 token，单次输出最多 1400 token，超时 180 秒，按指定数量串行处理；很长或特殊字符密集的正文需要后续分段策略，当前不声称完整覆盖。

统一收件箱已接入按需摘要：打开邮件后点击“生成摘要”，后端通过当前登录会话校验邮箱归属，再调用本地模型；不自动批量处理历史邮件，也不持久化该网页摘要。失败会明确提示并允许重试。

接口为 `POST /api/v1/email-connections/{connection_id}/messages/{message_id}/summary`，受现有登录、Origin 和 CSRF 校验保护。请求不接受客户端提供正文或用户身份。当前单进程服务一次处理一封，忙时返回 503，模型超时或不可用返回 503，校验不通过返回 502；模型调用期间不保持数据库读事务。

首页已接入后台自动检测、摘要与分类，通知与结果加密持久化，详见 [自动邮件处理](AUTO_MAIL.md)。保留用户的 `SYSTEM_PROMPT`，在请求中附加类别枚举及结构化日期逐字引用约束，分类和摘要在同一次本地调用中生成。独立“邮件摘要”菜单与首页 AI 对话仍未实现。

## 新 Mac 安装相同版本

适用于 Apple Silicon、macOS 14 或更新版本。下载和解压均在项目内执行：

```bash
mkdir -p .tools/ollama
curl -fL https://github.com/ollama/ollama/releases/download/v0.40.16/ollama-darwin.tgz -o .tools/ollama/ollama-darwin.tgz
```

对照官方发布的 SHA-256，必须匹配后再解压：

```bash
shasum -a 256 .tools/ollama/ollama-darwin.tgz
# a743717494315da7cd352982b805f6b992d4b4452ca117fd5fbf86c4ee46fca0
tar -xzf .tools/ollama/ollama-darwin.tgz -C .tools/ollama
bash scripts/ollama-serve.sh
```

另开终端下载模型（约 2.5 GB）：

```bash
OLLAMA_HOST=127.0.0.1:11434 .tools/ollama/ollama pull qwen3:4b-instruct-2507-q4_K_M
```

检查 GPU 使用情况：`OLLAMA_HOST=127.0.0.1:11434 .tools/ollama/ollama ps`。
