# 课程实时翻译：开发记录

**当前状态（2026-11-14）**：第 1–4 阶段已完成并在用户本机实际使用；第 5 阶段（系统评估）按用户决定暂缓，使用中发现问题再处理。**功能说明、接口和使用方法以 [LECTURE.md](LECTURE.md) 为准**；本文件保留开发过程中的决定和各阶段记录，第 1–5 节为最初计划，部分细节已被后续阶段修改（例如切句改为自写能量 VAD 而非 Silero，保存表单不再填写课程编号和授课老师）。

## 0. 已确认的决定

- **语音识别**：mlx-whisper（Whisper large-v3-turbo，Apple 芯片 GPU）。讲课均为英文，识别固定英文，翻译方向为英译中。
- **不保存录音**：音频只在内存中处理，处理完即丢弃。
- **两组按钮**：“开始课程 / 结束课程”界定一节课；课中可多次“暂停录音 / 继续录音”，每段连续录音为一个录音段。
- **实时翻译用 Qwen3 4B**（第 1 阶段实测后改定，见 0.1 节）：与邮件功能共用同一模型实例和 16K 上下文；上课期间翻译优先，邮件摘要等请求排队。结束课程后再用 Qwen 生成摘要。
- **结束课程后生成摘要**：按时间顺序合并各录音段，先逐段提炼要点，再汇总为整节课的摘要与重点。
- **保存由用户决定**：结束课程后可选择保存，需填写课程名称，可补充其他信息；也可以不保存，直接丢弃。
- **课堂笔记**：上课期间可自行记录笔记，笔记带时间点，与摘要一起保存。
- **翻译选型**：第 1 阶段对比了 Opus-MT、NLLB-200 蒸馏 600M 与 Qwen3 4B（Chrome 内置翻译在内嵌浏览器中不可用），结果见 `docs/LECTURE_BENCH.md`。
- **保存数量不设上限**：课程记录不限课程数和条数（纯文字，每节课约数十 KB）；取代最初“最多 5 门课”的设想。
- **逐句转写默认不保存**：保存表单中“逐句转写与译文”默认不勾选，需要时手动勾选。
- **已同意**：第 2 阶段新增 `lecture_records` 表（只新增，迁移前备份并在副本上验证回退）；第 1 阶段安装 mlx-whisper、CTranslate2 并下载实测模型权重（约 3 GB，放在 `private-data/models/`，选定后删除不用的模型）。

## 0.4 第 4 阶段完成情况（2026-11-13）

- 后端 `backend/app/lecture_summary.py` 与 `POST /api/v1/lecture-summaries`（需登录、Origin 与 CSRF）：请求体为本节课字幕 `lines[{at_seconds, en}]`（≤ 20000 句）和笔记；只返回结果，不写数据库、不写日志。不足 40 个英文词时返回 `LECTURE_SUMMARY_TOO_SHORT`，不调用模型。
- Map-reduce：按约 2500 词把字幕分成若干部分，每部分用英文提取 `mentions`（作业、考试与考试重点、截止、通知，先于知识点输出）和最多 12 条 `points`，均引用句子编号；最后一步用中文写概览、按部分组织的重点和课程安排提醒，引用 point / mention 编号。输出的 JSON schema 规定 `parts` 数组长度等于部分数，每部分 1–k 条（k = 12 ÷ 部分数，1–8），强制覆盖整节课；只用提示词要求“每部分至少一条”时 4B 模型仍会集中在开头。
- 程序负责证据：丢弃引用了不存在或不属于该部分的编号的条目，把编号换成时间点和最多两句英文原话（≤ 300 字符）；最终概览、重点、提醒任一组不是中文时重试一次；格式不合格重试一次。每次模型调用单独获取模型锁（等待上限 120 秒），所以长摘要期间实时翻译和邮件摘要可以穿插进行。
- 笔记只作为参考：重点笔记优先、最多 40 条，提示词要求不得把笔记当作老师所讲。
- 保存：`LectureRecordInput.summary` 接受上述结构（版本必须为 `lecture-summary-v1`，时间点不超过课程时长），与笔记一起加密保存；列表只返回 `has_summary`。
- 前端：结束课程且最后一句字幕处理完后自动生成，显示预计时间，可先填课程信息；生成后预览，“AI 摘要与重点”默认勾选，可重新生成；失败时提示原因并可重试，仍可只保存笔记。摘要暂存在本机草稿中（按字幕句数判断是否过期，返回课程继续录音后会重新生成），刷新不会重新调用模型。课程记录页显示概览、提醒、重点及可展开的原话，导出的 Markdown 也包含摘要。
- 实测见 `docs/LECTURE_BENCH.md` 第 5.3 节。
- 界面调整（2026-11-14，用户要求）：“结束课程”需二次确认（可选“继续上课”）；保存表单顶部显示“AI 课程摘要正在生成，请稍等”；保存与编辑表单不再填写课程编号和授课老师（接口仍接受这两个可选字段，旧记录中的值保留并显示）；课程记录列表以加粗课程名为标题，日期只显示“11.14”这样的月.日。

## 0.3 第 3 阶段完成情况（2026-11-13）

- 后端 `backend/app/lecture_stream.py`：WebSocket `/api/v1/lecture/stream`。握手后校验 Origin 与登录会话，同一账号同时只允许一个录音流；客户端发送 16 kHz 单声道 PCM16（每帧 ≤ 64 KB，单段最长 4 小时），文本消息 `{"type":"pause"|"stop"}`。服务端依次返回 `status`（loading / listening / stopped）、`caption`（id、相对本段的 offset、duration、英文）、`translation`（id、中文或 null）、`error`（固定代码与中文说明）。音频只在内存中，识别文字和译文不写日志、不落库。
- 切句：能量 VAD，阈值随环境噪声自适应但上限 0.04（防止连续讲话时阈值被语音本身抬高而“失聪”）；短句需 0.5 秒停顿，超过 3 秒后 0.18 秒停顿即可断句；满 7 秒时在最近 2 秒最安静处切开，余下部分并入下一句（2026-11-14 由 5 秒 / 12 秒缩短，见 `docs/LECTURE_BENCH.md` 5.4 节）。
- 临时英文（2026-11-14）：说话时约每秒识别一次未结束的句子，以 `{"type":"partial","offset","en"}` 发送（`en: null` 表示清除），页面灰色显示、不保存，整句字幕到达后替换。识别与翻译为两个并行任务。
- 识别：mlx-whisper large-v3-turbo，只从本机 `private-data/models/hf` 离线加载，关闭 `condition_on_previous_text`，以前文（≤ 200 字符）作提示，过滤 Whisper 在静音上的常见幻觉。翻译：Qwen3 4B，附前两句作上下文，与邮件功能共用模型锁和 16K 上下文；录音期间后台邮件摘要暂停排队，模型被占用超过 30 秒时该句跳过翻译而不阻塞字幕。
- 新增运行依赖 `websockets`（uvicorn 处理 WebSocket 所需）；Vite 代理开启 `ws`。
- 前端：AudioWorklet（`frontend/public/pcm-capture-worklet.js`）在 16 kHz AudioContext 中转为 PCM16，每 100 ms 一帧；首次录音需确认已获授权（按账号记在本机）；开始 / 暂停 / 继续录音，每段录音单独计时；双语字幕（时间、英文、中文或“翻译中…”），自动滚动且用户向上翻看时不打扰；麦克风音量条；离开页面自动关闭麦克风。上课中的字幕与笔记一起暂存在本机，结束课程时可勾选保存逐句转写与译文（默认不勾选），录音时长按实际录音段计算。
- 实测（`scripts/lecture-stream-test.py`，合成课程实时推流，真实模型）：句末到英文字幕中位数约 0.46 秒，到中文字幕中位数约 1.1 秒（P90 ≤ 1.5 秒，最长约 3 秒）；整段 WER 4.0%–5.1%；翻译失败 0。尚未用真人在真实课室中测试。

## 0.2 第 2 阶段完成情况（2026-11-13）

- “实时翻译”页：开始 / 结束课程、计时、带时间点的课堂笔记（回车添加、编辑、删除、标为重点；中文输入法组字时回车不提交）。录音按钮显示为“即将接入”且不可用，不模拟录音。
- 上课中的笔记按账号暂存在本机浏览器，刷新或关闭后可恢复；保存或丢弃后清除。
- 结束课程后的保存表单：课程名称（必填，可从已有课程名称中选择）、课程编号、授课老师、其他信息；可选择是否保存笔记；AI 摘要和逐句转写选项在第 2 阶段显示为待接入（已分别于第 4、3 阶段接入）。也可返回课程或确认后丢弃。
- 新增 `lecture_records` 表（迁移 c4d2e8f1a9b6，迁移前已备份并在副本上验证回退）。课程名称与编号为明文便于分组，授课老师、其他信息、笔记、摘要与转写加密保存。接口：`GET/POST /api/v1/lecture-records`、`GET/PATCH/DELETE /api/v1/lecture-records/{id}`，受登录、Origin 与 CSRF 保护，按账号隔离；不接受客户端提交摘要或转写。
- “课程记录”页：按课程分组，查看详情、编辑课程信息与笔记、删除（需确认）、导出 Markdown。

## 0.1 第 1 阶段实测结论（2026-11-13，详见 `docs/LECTURE_BENCH.md`）

- mlx-whisper large-v3-turbo：TED 演讲整段 WER 3.6%、实时模拟 6.5%，单句识别约 0.39 秒，显存峰值 2.8 GB，满足要求。
- 翻译：Opus-MT 与 NLLB 在课程术语上直接译错（Adam→亚当、Transformer→变压器、softmax→软峰值）；Qwen3 4B 质量远高（chrF 61.9 对 33），单句约 0.35 秒。因此改为上课期间用 Qwen3 4B 实时翻译，并处理与邮件摘要的模型争用（已确认，见下方决定）。
- Chrome 内置翻译在 Claude 应用内嵌浏览器中不可用，暂不考虑。

**决定（2026-11-13）**：实时翻译只用现有的 Qwen3 4B 一个模型，沿用应用的 16K 上下文（避免切换上下文导致模型重载，显存约 5.1 GB，加 Whisper 合计约 8 GB）。上课期间翻译优先，邮件摘要、回复与起草请求排队，在翻译空隙或下课后处理，不另开模型实例。Opus-MT 与 NLLB 不再使用，已删除。这取代第 0 节中“上课期间不调用 Qwen”的决定。

## 1. 使用流程

```
[开始课程] ─▶ 录音中 ⇄ 已暂停 （[暂停录音] / [继续录音]，可多次）
                 │        │        上课期间随时写笔记，自动记录时间点
                 └────────┴─▶ [结束课程]
                                  │
                                  ▼
                      Qwen 按录音段顺序生成摘要和重点（约 1–3 分钟）
                                  │
                                  ▼
               保存表单：课程名称（必填）、课程编号、授课老师、其他信息
               选择保存：AI 摘要与重点 ☑ / 我的笔记 ☑ / 逐句转写与译文 ☐
                                  │
                   ┌──────────────┴──────────────┐
                [保存到课程记录]                [不保存，丢弃]
```

- **计时**：显示本节课总时长和当前录音段时长；暂停期间不计入录音时长，但笔记照常可写。
- **意外关闭**：上课期间的笔记、转写和译文自动暂存在本机浏览器（不上传），刷新或意外关闭页面后可以恢复；结束课程并作出保存或丢弃的选择后清除暂存。
- **同时只能有一节进行中的课程**。

## 2. 课堂笔记

- 实时字幕旁边是笔记栏。输入后按回车添加，每条自动标上课程内时间（如 23:10），可编辑、删除，可标为“重点”。
- 在课程时间线上，笔记与字幕按时间交错显示，方便对照老师当时在讲什么。
- 生成摘要时，笔记作为辅助输入提供给 Qwen，标记为“学生笔记”，与“老师原话”区分；用户标为重点的笔记优先纳入总结。摘要中只引用转写原文作为老师所说的证据，笔记内容不会被写成老师说的话。
- 不开启录音也可以只用笔记功能（例如老师禁止录音的课）。

## 3. 架构

```
浏览器麦克风 ─16 kHz PCM─▶ WebSocket ─▶ VAD 切句 ─▶ mlx-whisper（英文）
                                                       │ 英文句子 + 时间戳
                                    ┌──────────────────┴─────────────────┐
                                    ▼                                    ▼
                        Qwen3 4B 逐句翻译（优先）               内存中的本节课转写
                                    │                                    │
                                    ▼                                    ▼
                           双语字幕（原文 / 译文）        结束课程：Qwen 分段摘要 → 汇总
```

- **前端**：`getUserMedia` 取麦克风，AudioWorklet 降采样为 16 kHz 单声道 PCM，经 WebSocket 每 100–200 ms 发送一帧；暂停录音时停止采集并释放麦克风。`127.0.0.1` 属于安全上下文，可以使用麦克风。
- **后端**：FastAPI WebSocket `/api/v1/lecture/stream`。握手时校验登录会话和 Origin（现有 CSRF 中间件只覆盖 HTTP 写请求，WebSocket 必须单独校验）。日志不记录任何识别文字。
- **翻译**：后端每识别出一句，即交给 Qwen3 4B 翻译并随字幕推回。翻译请求优先获得模型；邮件摘要、回复和起草请求在翻译空隙排队执行。已在进行中的一次邮件摘要不会被打断，最多让字幕延迟一次（约 5–15 秒）。
- **摘要**：结束课程时提交本节课的转写和笔记，Qwen 先逐段（每段约 10 分钟或一个录音段）提炼要点，再合并为整体摘要和 5–8 个重点，每条重点附转写原文时间点。期间共用现有模型锁，与邮件摘要排队。

## 4. 模型候选

| 用途 | 方案 | 说明 |
|---|---|---|
| 语音识别 | **mlx-whisper + Whisper large-v3-turbo**（已确定） | 英文讲课准确率高，使用 GPU |
| 切句 | Silero VAD | 按停顿切句，避免翻译半句话 |
| 翻译 | **现有 Qwen3 4B**（已确定） | 课程术语翻译准确（chrF 61.9），单句约 0.35 秒 |
| 摘要 | 现有 Qwen3 4B | 结束课程后分段摘要再合并 |

模型权重放在 `private-data/models/`，不进 Git；版本以实测时最新稳定版为准。

## 5. 数据与存储

只在用户选择保存时写入数据库。计划新增一张表（需要数据库迁移，见第 8 节）：

- `lecture_records`：`id`、`user_id`、课程名称（必填，≤100 字）、课程编号、授课老师、上课日期、开始与结束时间、录音总时长，以及加密保存的：其他信息（自由文本，≤2000 字）、AI 摘要与重点（含时间点）、笔记（含时间点、是否重点）、可选的逐句转写与译文。

记录数量不设上限，由用户自行删除，系统**不自动删除**。加密复用现有 Fernet 密钥；记录按账号隔离。

“课程记录”页面：按课程分组和日期列出；查看摘要、重点、笔记（及转写，如已保存）；可编辑课程信息、其他信息和笔记；可删除；可导出 Markdown 文本。

## 7. 评估方法（可用于 NLP 课程报告）

- **语音识别**：英文词错误率（WER），分安静与嘈杂教室音频。
- **翻译**：约 50 句人工参考译文，计算 chrF / BLEU，并按“准确、通顺、术语”人工打 1–5 分；记录每句延迟。
- **实时性**：从老师说完一句到译文出现的端到端延迟（中位数和 P90）。
- **摘要**：人工标注重点，计算模型重点的召回率与准确率；检查时间点引用是否对应原话；比较“有笔记 / 无笔记”两种输入下的摘要质量。

3. **数据库迁移**：同意第 2 阶段新增 `lecture_records` 表。
4. **新增依赖**：同意第 1 阶段安装 mlx-whisper、CTranslate2 并下载实测模型权重。
5. **录音许可**：开始录音前页面提醒“请确认已获得授课老师和学校允许”；是否允许转写课堂内容由用户自行按学校和课程规定确认。实测只使用公开授权的讲座音频。

## 9. 主要风险

- 教室噪音和远距离收音会明显降低识别率：建议使用耳机麦克风或靠近讲台；实测包含嘈杂音频。
- 翻译与邮件功能共用一个模型：邮件摘要正在运行时，字幕可能短暂延迟；可支持每门课的术语表以进一步统一译法。
- 长时间运行的内存与发热：第 3 阶段做 90 分钟压力测试。
- 结束课程时的摘要耗时：一节 90 分钟课程需多次调用 Qwen，界面显示进度，用户可以先保存笔记，摘要完成后再补入。
