# Mac App 与介绍网站开发计划（2026-11-15 起草，待确认）

> 目标：把 HK Mate 做成可下载安装的 Mac App，并做一个介绍网站，说明功能和用法、提供下载。
> 结论：**先做网站（轻量版），再改造并打包 App**。理由见第 2 节。整体约 3–4 周（单人开发）。

## 1. 现状与约束

| 项 | 现在 | 做成 App 需要 |
|---|---|---|
| 运行方式 | 终端运行 `scripts/dev.sh`，后端 + Vite 两个进程 | 双击打开的 App，一个进程，不需要终端、Node 或 Python |
| 数据 | 项目里的 `private-data/`（数据库、密钥、模型） | 放到 `~/Library/Application Support/HK Mate/`；加密密钥放进 macOS 钥匙串 |
| 本地模型 | 项目内 Ollama + Qwen3 4B（约 2.5 GB），mlx-whisper 识别 | App 自带或引导安装 Ollama，首次启动下载模型并显示进度 |
| 系统要求 | 本机 Apple Silicon | 只支持 Apple Silicon（mlx-whisper 依赖）；建议 16 GB 内存、约 6 GB 空间 |
| Gmail 登录 | “网页”类型 OAuth 客户端，配置文件在本机 | 改为 Google “桌面应用”类型客户端（回环地址 + PKCE，PKCE 已有） |
| AI 助手密钥 | 写在 `private-data/agent.env` | 每位用户在 App 设置里填写自己的 Key（不填则 AI 助手不可用，其余功能照常） |

### 必须提前知道的两个外部限制

- **Google（Gmail 只读权限属于“受限权限”）**
  - 测试模式：最多 100 位手动添加的测试用户，授权约 7 天过期需要重新连接。课程项目、同学试用足够。
  - 公开给任何人用：需要 Google 审核，要求有公开网站首页、隐私政策页、域名验证、演示视频，并可能需要第三方安全评估（CASA）。耗时数周，可能有费用。
- **Apple**
  - 不加入 Apple Developer Program 也能分发，但用户第一次打开会被系统拦截，需要右键“打开”。
  - 加入（每年 99 美元）后可签名和公证，用户双击即可打开。

## 2. 为什么先做网站

1. **快**：网站 2–3 天能上线，马上有可以展示和分享的东西；App 打包前还有大量改造。
2. **Google 需要它**：Gmail 授权页（OAuth 同意屏幕）和将来的审核都要求公开首页和隐私政策页。先上线网站，后面不会卡住。
3. **文档复用**：网站上的“使用指南”就是 App 的用户手册，写一次两边用。
4. **截图时机好**：界面刚改版完成，正适合截图。截图一律用合成数据，不出现真实邮件或姓名。

## 3. 阶段计划

### 第 0 步：先定几件事（半天）

- 面向谁：只给自己和同学（≤ 100 人，走 Google 测试模式），还是公开发布（要走 Google 审核）。
- GitHub 仓库是否公开；网站放 GitHub Pages（免费，地址形如 `用户名.github.io/hk-mate`）还是买域名。
- 是否加入 Apple Developer Program。
- App 名称与图标：沿用“HK Mate”和衬线标志。

### 第 1 阶段：介绍网站（2–3 天）

- **页面**：
  - 首页：一句话介绍、主截图、下载按钮（App 完成前写“即将推出”）。
  - 功能：今天首页、日程与课表、邮件分类 / 摘要 / 回复草稿、课堂实时翻译与课程记录、HKU 指南、AI 助手。
  - 使用指南：安装、连接 Gmail、导入课表、上课翻译、常见问题。
  - 隐私说明：哪些数据只在本机、Gmail 只读、哪些内容会发给云端 AI（只有 AI 助手对话）。
  - 系统要求与常见问题。
- **技术**：仓库内新建 `website/`，沿用现有 Vite + React 和同一套设计变量，输出纯静态页面；不引入新框架。
- **部署**：GitHub Pages，推送到 main 后由 GitHub Actions 自动发布。这也顺带建立仓库的第一个 CI（审阅报告第 16 项）。

### 第 2 阶段：App 化改造（1–1.5 周，代码层面，打包前必须完成）

1. 数据目录迁到 `~/Library/Application Support/HK Mate/`，首次启动时迁移旧数据，并先备份。
2. 加密密钥存入 macOS 钥匙串。
3. 首次使用向导与“设置”页：
   - 检查本地模型、下载模型并显示进度；
   - 连接 Gmail；
   - 可选填写 AI 服务商和 Key（替代手改 `agent.env`）；
   - 导入课表。
4. 单进程运行：后端直接提供构建好的前端（`scripts/serve.sh` 已经支持），不再需要 Vite 和 Node。
5. 本地模型：App 内附 Ollama 程序（MIT 许可），模型首次启动下载；mlx-whisper 模型同样首次使用时下载。
6. Gmail 改用“桌面应用”类型 OAuth 客户端。

### 第 3 阶段：打包 Mac App（约 1 周）

- **建议方案**：pywebview（原生 macOS 窗口，WKWebView）+ PyInstaller 打包 Python 后端，产出 `.app` 和 `.dmg`。
  - 全程 Python，不新增 Rust 或 Electron。
  - 安装包较小。
  - 需要新增依赖 pywebview 和 PyInstaller，按项目规则需要确认。
- **另外两个方案**：
  - Electron：成熟，但多带一整套 Chromium 和 Node，安装包大 150 MB 以上。
  - Tauri：体积小，但需要引入 Rust 工具链。
- **菜单栏图标**：关闭窗口后仍在后台检测新邮件、生成摘要和分类；可以从菜单栏重新打开或退出。
- **签名与公证**：需要 Apple 开发者账号；没有账号时，在网站上写明“右键打开”的步骤。
- **测试**：在一台干净的 Mac 上，从下载 dmg 到第一次成功使用完整走一遍。

### 第 4 阶段：发布（2–3 天）

- dmg 放到 GitHub Releases，网站的下载按钮指向最新版本。
- 版本号与更新提示：App 启动时检查 GitHub 上的最新版本并提示下载；自动更新（Sparkle）以后再做。
- 网站补上安装截图和“第一次使用”视频或动图。

## 4. 时间线（单人开发，约 3–4 周）

| 周 | 内容 |
|---|---|
| 第 1 周 | 第 0 步决定；网站上线（含隐私说明）；开始 App 改造（数据目录、钥匙串） |
| 第 2 周 | 首次使用向导与设置页、模型下载、Gmail 桌面客户端 |
| 第 3 周 | pywebview 打包、菜单栏、dmg、干净 Mac 测试 |
| 第 4 周 | 签名与公证（如加入开发者计划）、发布、网站补下载与安装指南 |

如果要公开发布并走 Google 审核，审核从网站上线后开始提交，时间另计（通常数周）；在此期间，App 可以先以测试模式给最多 100 位同学使用。

## 5. 需要确认的事项

- [ ] 面向范围：自己和同学（测试模式），还是公开发布（Google 审核）
- [ ] 网站地址：GitHub Pages 还是自有域名；仓库是否公开
- [ ] 是否加入 Apple Developer Program
- [ ] 打包方案：pywebview + PyInstaller（建议）、Electron 或 Tauri
