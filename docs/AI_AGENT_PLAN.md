# 首页 AI 助手（Agent）：开发计划框架

状态：第 2 版（2026-11-14）。**已确认：Agent 只用云端模型，不用本地 Qwen**；海外与大陆服务商都要支持，先接 OpenAI（ChatGPT）接口；项目将来可能推广为 UK mate，需支持多地区（第 10 节）。已完成模型接口层（第 4.3 节）与对话骨架（第 7 节阶段 1b，见第 11 节）；第 9 节其余决定确认前不新增依赖、密钥、数据库表或外部服务。

## 1. 目标与范围

把首页“给今天一点灵感 → 与 AI 对话”的预留界面变成一个能**理解需求、调用工具、给出可操作结果**的助手。第一版覆盖四类需求：

| 类别 | 例子 | 主要数据来源 |
|---|---|---|
| 吃喝 | “HKU 附近有什么好吃的川菜？”“现在还开着的咖啡馆” | Google Places API |
| 玩 | “周末去哪里行山，新手路线”“铜锣湾买电子产品去哪” | 精选知识库 + Google Places + 天文台天气 |
| 办事知识 | “怎么办 HKID？”“学生开银行账户要带什么？”“八达通学生优惠” | 精选知识库（官方来源，注明核对日期） |
| 用系统 | “帮我给 Prof. Chan 写封邮件，明天的课请假”“这周有哪些 deadline”“上节 NLP 课讲了什么” | 现有功能：日程、邮件起草、课程记录 |

**不做**：自动发送邮件（仍只有 gmail.readonly）、删除或修改邮件、代替用户付款 / 预订 / 报名、开放式联网搜索（第一版）、记住跨会话的长期记忆。

## 2. 总体架构

```
前端 AgentChat（首页）
   │  POST /api/v1/agent/chat（SSE 流式：文字增量、工具状态、结果卡片）
   ▼
AgentRuntime（后端，单次请求内的循环，最多 6 步）
   ├─ 选择 Skill：按用户问题匹配，只把相关 Skill 的说明和工具交给模型
   ├─ ChatModel：云端模型（OpenAI 及兼容接口；按配置切换服务商）
   ├─ ToolRegistry：工具名、说明、JSON 参数 schema、权限级别、执行函数
   │     ├─ 只读工具：直接执行（查地点、查知识库、查日程、查天气）
   │     └─ 写操作工具：只生成“待确认卡片”，用户点确认后才由前端调用现有接口
   └─ 结果卡片：地点卡、知识卡（带来源）、邮件草稿卡、日程确认卡
```

设计原则：

- **简单单体**：不引入 LangChain 等通用 Agent 框架（AGENTS.md 第 5 节），自己写一个约 200 行的循环，工具即普通 Python 函数，复用现有业务模块。
- **模型只决定“调用什么”，不直接动数据**：写操作一律由用户在卡片上确认；模型输出、邮件内容、地点评论、知识库文本都视为不可信数据。
- **结构化结果给界面，简短摘要给模型**：例如邮件草稿完整显示在卡片里，回传给模型的只有“草稿已生成”，减少隐私数据进入模型上下文。
- **可替换的服务商**：所有服务商走同一个 `ChatModel` 接口，换服务商只改配置（第 4 节）。

## 3. Skill 设计

**Skill = 一个场景的“工作说明书”**：一段 Markdown，写明什么时候用、可用哪些工具、回答的步骤和注意事项。运行时先用便宜的方法（关键词 + 模型一次分类）选出 1–2 个 Skill，只把它们的说明和工具交给模型，这样工具列表短，小模型也更不容易选错。

```markdown
---
name: food-nearby
description: 推荐 HKU 或指定地点附近的餐厅、甜品、咖啡馆
tools: [places_search, place_details, get_weather]
---
1. 没说地点时默认港大本部（Pok Fu Lam Road）……
2. 先确认类别（中餐 / 西餐 / 甜品 / 咖啡……）和是否需要“现在营业”……
```

| Skill | 用途 | 使用的工具 | 要点 |
|---|---|---|---|
| `food-nearby` 附近美食 | 中餐、西餐、日韩、甜品、咖啡馆、茶餐厅；可按营业中、距离、评分、价位筛选 | `places_search`、`place_details` | 默认地点为港大本部，也支持“西营盘站附近”；结果以卡片展示（评分、价位、营业状态、步行距离、Google 地图链接）；不编造店铺 |
| `hk-explore` 香港游玩 | 购物区、景点、行山路线、雨天去处 | `knowledge_search`、`places_search`、`get_weather` | 行山路线来自精选知识库（难度、时长、交通、起终点）；**行山前检查天文台警告**（暴雨、酷热、雷暴、台风时提示不宜出行） |
| `newcomer-guide` 新生办事 | HKID、银行开户、八达通与学生乘车优惠、电话卡、学生签证延期、医疗等 | `knowledge_search` | 只依据知识库回答并附官方来源链接与核对日期；知识库没有的内容说“不确定，请查官方网站”，不凭记忆回答费用、时限和材料清单 |
| `mail-assistant` 邮件助手 | 请假、延期申请、约 office hour、询问成绩等 | `schedule_list`、`contact_lookup`、`show_draft`、`open_page` | 例：“明天的课请假” → 查明天课程 → 确认是哪门课 → 模型写草稿 → 草稿卡片（可编辑、复制、在“起草邮件”中打开）。缺信息时先问用户，不猜教授邮箱 |
| `schedule-assistant` 日程助手 | “明天有什么课”“这周有哪些 deadline”“帮我加一个周五交作业的提醒” | `schedule_list`、`schedule_propose_event` | 添加日程只生成确认卡片，用户点“确认添加”后才写入 |
| `lecture-review` 课程回顾 | “上节 NLP 课讲了什么”“哪节课提到考试范围” | `lecture_records_search` | 只读已保存的课程记录与摘要，引用时间点 |
| `app-help` 系统帮助 | “怎么连接 Gmail”“实时翻译怎么用” | `knowledge_search`（系统文档）、`open_page` | 知识来自本项目 docs 的使用说明部分 |
| （兜底）闲聊 | 不属于以上类别 | 无 | 简短回答，说明能帮什么；不提供医疗、法律、投资的确定性建议 |

## 4. 模型选择

### 4.1 决定（2026-11-14）

Agent 只用云端模型。原因：多步任务（查课程 → 起草邮件 → 按反馈修改）和开放问答需要较强的模型；本地 Qwen3 4B 还要同时承担实时翻译和邮件摘要，共用一个模型锁会排队。现有功能（邮件摘要、回复草稿、课程翻译与课后摘要）仍用本地 Qwen，不受影响。

### 4.2 服务商

| 服务商 | 地区 | 接口 | 状态 |
|---|---|---|---|
| OpenAI（ChatGPT） | 海外 | **Responses API**（新模型只在此接口调用工具）；Chat Completions 适配器保留给兼容服务 | **已实现并用真实密钥验证**（2026-11-14，gpt-6.1-terra） |
| Google Gemini | 海外 | OpenAI 兼容接口 | 共用适配器，未用真实密钥验证 |
| Anthropic Claude | 海外 | 原生 Messages API | 已登记，需单独适配器 |
| 通义千问（阿里云国际 / 百炼） | 海外 / 大陆 | OpenAI 兼容接口 | 共用适配器，未验证 |
| DeepSeek | 大陆 | OpenAI 兼容接口 | 共用适配器，未验证 |
| Kimi（月之暗面） | 大陆 | OpenAI 兼容接口 | 共用适配器，未验证 |
| 智谱 GLM | 大陆 | OpenAI 兼容接口 | 共用适配器，未验证 |
| 其他兼容服务 | — | 自填 `HKM_AGENT_BASE_URL` | 共用适配器 |

- 各家地址按其公开文档预置在 `backend/app/agent/providers.py`，启用某家前须再对照官方文档核对地址、模型名和工具调用支持情况。
- **地区可用性**：部分海外服务（包括 OpenAI）不对香港等地区开放，接口会返回 `AGENT_REGION_UNSUPPORTED`；大陆服务商通常需要大陆实名账号。实际部署前需确认所选服务在用户所在地区合法可用，以及数据使用条款。
- 模型名不写死在代码里，由 `HKM_AGENT_MODEL` 指定（以服务商当时的模型列表为准）。

### 4.3 已实现的接口层（`backend/app/agent/`）

- `providers.py`：服务商预置（地区、接口类型、地址、状态）和 `AgentSettings`（从环境变量读取；密钥不进入 repr、日志、响应和错误信息；非 HTTPS 地址拒绝使用）。
- `models.py`：与服务商无关的 `ChatModel.complete(messages, tools) -> ModelTurn` 接口；`OpenAIChatModel` 用现有 httpx 直接调用 `/chat/completions`（不新增 SDK 依赖），支持函数工具调用、多个并行工具调用、工具结果回传；新模型用 `max_completion_tokens`，兼容服务用 `max_tokens`；默认不发送 temperature（部分新模型只接受默认值）。错误统一为固定代码：密钥无效、地区不支持、额度不足、限流、超时、上下文过长、模型不存在、服务不可用、响应格式错误；服务商返回的原文不进入错误信息。限流与 5xx 自动重试一次。
- `runtime.py`：工具调用循环 `AgentLoop`。工具 = 名称 + 说明 + Pydantic 参数模型 + 执行函数；参数先校验再执行；未知工具、参数错误、工具异常都以简短错误回传给模型而不中断对话（不回传异常细节）；用户身份由调用方通过 `context` 传入，模型无法指定；工具返回“给模型的简短结果”和“只给界面的卡片”两部分；最多 6 步，最后一步不再提供工具、强制作答；累计 token 用量。
- 测试：`backend/tests/test_agent_models.py`（模拟 HTTP，不访问真实服务）。
- 连接检查：`scripts/agent-model-check.py`，只发送一个合成的乘法问题，验证密钥、地区和完整的工具调用往返；每次运行产生一次计费调用。

### 4.4 隐私边界（随“只用云端”调整，待确认）

问题本身和工具结果都会发给云端服务商，因此：

- 邮件草稿由云端模型直接撰写（不再调用本地 Qwen），只生成草稿、不发送；收件人邮箱地址只在本机查找和显示，不发给模型。
- 不把邮件正文发给云端模型（第一版没有“读邮件”工具）；日程、课程记录只回传回答所需的字段。
- 首次使用前提示“对话内容会发送给所选的云端服务商”，由用户确认。

## 5. 工具清单

权限级别：**R** 只读，自动执行；**P** 提议，只生成卡片，用户确认后由前端调用现有接口；**L** 本地执行，结果不完整回传给云端模型。

| 工具 | 级别 | 参数（简） | 实现 | 说明 |
|---|---|---|---|---|
| `places_search` | R | `query`、`category`、`near`（默认港大本部）、`open_now`、`max_results≤8` | Google Places API（New）Text Search | 用 field mask 只取需要的字段控制费用；返回名称、评分、评论数、价位、营业状态、地址、坐标、Google 地图链接 |
| `place_details` | R | `place_id` | Places API（New）Place Details | 营业时间、电话、网站；按需调用 |
| `knowledge_search` | R | `topic`（newcomer / explore / app）、`query` | 本地 Markdown 知识库检索 | 返回段落、来源 URL、核对日期 |
| `get_weather` | R | — | 现有 `weather.py`（天文台） | 包括当前警告，供行山与出行建议 |
| `schedule_list` | R | `start_date`、`end_date`、`kind?` | 复用日程查询（需从 `calendar_api.py` 抽出） | 按账号隔离，日期按香港时间 |
| `schedule_propose_event` | P | 标题、日期、时间或截止时间、地点 | 只返回确认卡片 | 用户确认后前端调用 `POST /api/v1/calendar/events` |
| `lecture_records_search` | R | `course?`、`date_from?`、`query?` | 现有课程记录（解密后在本机检索） | 返回摘要要点与时间点 |
| ~~`contact_lookup`~~ | — | — | 已取消（2026-11-14）：收件人邮箱由用户在卡片中填写 | — |
| `show_draft` | P | `subject`、`body`、`recipient_name` | 云端模型写好草稿后调用，生成草稿卡片 | 可编辑、复制、“在起草邮件中打开”；收件人地址由用户在卡片中选择；不发送 |
| `open_page` | P | `page`（inbox、compose、calendar、lecture……） | 前端导航 | 例如“带我去实时翻译” |

后续可选：`route_time`（Google Routes API，交通时间）、`web_search`（需另行评估信息可靠性与注入风险）。

### 5.1 Google Maps 接入要点

- 需要 Google Cloud 项目、启用 Places API（New）、API Key 与结算账户；密钥放 `private-data/agent.env` 的 `HKM_AGENT_GOOGLE_MAPS_API_KEY`（以后其他地图类 API 共用这个 Key，在 Google Cloud 中限制可用的 API），只在后端使用，不进前端、Git、日志。
- 遵守 Google Maps Platform 条款：展示 Google 归属标识；除 place_id 外不长期缓存地点内容；链接回 Google 地图。
- 费用控制：field mask 最小字段、每账号每日调用上限、同一查询短时间去重；超限时明确提示。
- 备选：OpenStreetMap（免费，但香港餐厅评分、营业时间数据较少）。

### 5.2 知识库

- 形式：`backend/app/agent/knowledge/` 下的 Markdown，每篇一个主题（如 `hkid.md`、`bank-account.md`、`octopus.md`、`hiking-beginner.md`），frontmatter 写来源 URL、核对日期、适用对象。
- 内容来源以官方为主：入境事务处、港大学生事务相关页面、八达通、各银行官网、渔农自然护理署郊野公园、香港旅游发展局等。由开发者整理、标注来源，不复制大段原文。
- 检索：第一版文章少（几十篇），用关键词 / BM25 即可，不引入向量数据库；超过一定规模再考虑本地嵌入模型。
- 过期提醒：回答中显示“资料核对于 YYYY-MM-DD”；超过 6 个月的条目在检查脚本中提示复核。

## 6. 安全与隐私

- 接口沿用登录、Origin、CSRF；工具执行时身份来自会话，**不接受模型给出的 user_id**。
- 写操作只能经用户点击确认；模型、邮件内容、地点评论、知识库文本里的指令都不执行。
- 不发送邮件；不新增 Gmail 权限。
- 限流：每账号每分钟、每日对话次数；云端模型与 Google API 的每日费用上限。
- 日志只记录工具名、耗时、错误代码，不记录对话内容、地点查询词或邮件内容。
- 对话第一版只保存在当前浏览器页面（刷新即清空），不入库；如需历史记录另行确认（会新增数据库表）。
- 提示注入测试：在邮件、地点名称、知识库中放入“忽略指令”“替我发送”等内容，确认不会触发写操作或泄露其他数据。

## 17. 对话历史与记忆（2026-11-14）

按用户决定：对话自动保存、只保留最近 **20** 个；记忆**自动记录并提示**（可一键撤销）。

- **数据库**：新增 `agent_conversations`（标题、滚动摘要、消息，整体 Fernet 加密）与 `agent_memories`（每条事实单独加密），均按 `user_id` 隔离（迁移 `d5e3f7a1b2c8`，只新增表；迁移前已在线备份到 `private-data/backups/hkumate-before-agent-history-*.sqlite3`，并在副本上验证升级 / 回退 / 再升级且原有数据不变）。
- **保存模式**：`POST /api/v1/agent/chat` 发送 `{"message", "conversation_id"?}`，服务器保存问答并先推送 `conversation` 事件（新对话的 id 与标题）；旧的 `messages` 无状态模式保留（脚本与测试使用），不保存。助手回复的卡片一并保存，但 **Google 地图的地点详情不保存**（Google Maps Platform 条款），历史中显示为“地点结果未保存，可重新搜索”。失败的回答以错误提示保存，不发给模型。
- **对话压缩**：模型始终收到最近 20 条消息（10 轮）原文；未进入摘要的消息超过 40 条（20 轮）时，在回答发出后由模型把更早的部分并入“先前对话摘要”（≤ 300 字），之后每次请求发送“摘要 + 最近 10 轮”。摘要随对话保存，从历史中继续对话时同样生效。
- **长期记忆**：工具 `remember`（不显示为步骤，回复中显示“已记住：… · 撤销”）。每条 ≤ 60 字，只记用户关于自己的长期信息（饮食偏好、预算、专业、住处、回复偏好），不记一次性事务、他人信息、健康细节；程序拒绝含密码 / 验证码、8 位以上数字、类似 HKID 或邮箱的内容。所有记忆以 `[id前8位] 事实` 的形式加入每次对话的系统消息；用户信息变化时模型传 `replaces` 更新原条目而不是新增矛盾条目。超过 30 条时由模型合并去重到 ≤ 20 条（合并结果同样经过敏感信息过滤），失败则保留最新 20 条。
