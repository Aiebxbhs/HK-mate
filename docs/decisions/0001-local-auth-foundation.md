# 0001：本地账号与页面基础

状态：已实施。范围：注册、登录、退出、会话恢复、账号首页及本地运行。

## 背景

项目由一人开发，优先支持本地运行，未来按实际需要接入邮箱和小模型。当前应交付可运行的账号功能，不引入云端身份依赖。

## 决定

- 后端 Python 3.13、FastAPI，uv 管理 `.venv` 与 `uv.lock`。
- 前端 React + JavaScript + Vite，npm 管理 `package-lock.json`，Node 24 项目内安装。
- 当前页面较小，先用 JavaScript；若后续采用 TypeScript，单独评估迁移，不混合两套约定。
- SQLite + SQLAlchemy + Alembic，数据库文件在忽略的私有目录中。
- Argon2id 哈希密码；服务端保存会话令牌哈希，浏览器保存 HttpOnly、SameSite=Lax Cookie；HTTPS 时启用 Secure。
- 写请求使用有签名、有时效的 CSRF Cookie/请求头组合及 Origin 白名单；前端每次写操作前获取令牌。
- 身份查询与权限校验在后端执行；前端只展示已验证的用户字段。
- 限流记录持久化，基于来源和账号两个维度；不信任未配置的转发头。
- 开发使用 Vite 同源代理，部署模式由 FastAPI 提供构建产物，不依赖外部 CDN 字体或脚本。
- VS Code 使用集成浏览器预览，保留普通浏览器作为兼容入口。

## 取舍

- 单实例，不引入 Redis 或分布式会话基础设施；多实例需要重新设计 CSRF 密钥配置和数据库并发策略。
- 使用账号和密码注册，不收集注册邮箱，展示名默认取账号。新账号为 3–32 位字母、数字或下划线，不区分大小写。
- 新迁移保留旧版邮箱账号及密码、会话；旧邮箱字符串作为兼容账号标识。
- 不自动绑定邮箱、不实现找回密码。界面不展示伪功能入口。
- 模型与邮箱供应商仍待定，不安装模型依赖或下载权重。
- npm 开发工具的 minimatch 依赖使用修复版 override，保留实际 Lint 和测试验证；后续依赖升级时复查是否仍有必要。

## 验证

仓库提供 `bash scripts/check.sh`。后端测试使用迁移后的独立临时 SQLite 数据库；前端测试覆盖表单、错误、会话恢复及 API 协议。真实浏览器视觉验收与测试环境的 DOM 交互检查是不同环节，不互相替代。
