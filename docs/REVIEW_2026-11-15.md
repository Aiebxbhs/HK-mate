# HK Mate 系统审阅报告（2026-11-15）

> 视角：一名在读的港大授课式研究生（TPg），第一次拿到 HK Mate，从开学到期末会怎么用它。
> 方法：在本机运行的应用里逐页走查（桌面与手机宽度），并阅读前后端代码、样式和项目文档。
> 未实测的部分：真实 Gmail 授权与邮件摘要、AI 对话的回答质量（会调用收费云端模型）、带真实录音的课程翻译。这些部分的结论来自代码和文档，不来自实际使用。

---

## 一、总体印象

作为学生，我会觉得这个应用**懂港大、懂我的一天**：课表能一键从 HKU Event Calendar 导入，英文课能实时出中文字幕和课后摘要，邮件会自动摘要，AI 能查我的课表、帮我写请假邮件、找附近吃的，图书馆哪层能彩印也一目了然。功能的“含金量”很高，而且处处体现了对隐私的克制（录音不落盘、邮件不发云端、链接不保存）。

但第一次打开时，我的感受是**“安静、干净，但有点像一份文档而不是一个产品”**：页面以浅绿和米白为主，字很小、灰字很淡，每个页面结构几乎一样，最有用的信息（下一节课、今天的截止事项）藏在下拉菜单里。功能强、表现弱，这是现在最大的反差。

---

## 二、做得好的地方（应保留）

1. **港大场景贴合度高**：课表导入教程按 HKU Portal 实际界面截图；指南只用官方来源并标注核对日期；图书馆逐层设施和打印机核对到每台编号。
2. **隐私设计到位**：课堂录音只在内存、邮件正文不发云端模型、课表链接用完即弃、密钥只放环境变量、所有数据按账号隔离。这一点在同类学生工具里很少见，值得在产品文案里讲出来。
3. **AI 不越权**：起草邮件不发送、添加日程要用户确认、天气查不到会直说，符合学生对“AI 别乱来”的期待。
4. **工程质量扎实**：后端 256 项、前端 105 项测试全部通过；登录有频率限制、写接口有 Origin 与 CSRF 校验；文档详细，决策都有记录。

## 三、不足之处（按优先级）

### P0 —— 现在就该处理的风险

| # | 问题 | 为什么重要 | 建议 |
|---|---|---|---|
| 1 | **代码几乎全部没有进 Git**：仓库只有 3 个文档提交，`backend/`、`frontend/`、所有迁移和测试都是未跟踪文件，当前在 `docs/development-guidelines` 分支 | 电脑一出问题，几周的开发全部丢失；也无法回退某次改坏的修改 | 立刻在新分支提交（确认 `private-data/` 已被忽略），推到 GitHub 私有仓库；之后按小功能提交 |

| 3 | **可读性不达标**：样式里有 148 处字号 ≤ 12px（最小 8px）；常用的浅灰文字 `#7d8f6e`、`#8a9a7c`、`#94a186` 在米白背景上的对比度只有 2.5–3.4 : 1，低于无障碍标准 WCAG AA 要求的 4.5 : 1 | 在课室投影下、手机强光下、或视力一般的同学，很多说明文字基本看不清 | 正文最小 13–14px、辅助文字最小 12px；浅灰统一换成对比度 ≥ 4.5 的颜色（如已在用的 `#5f7254`，对比度 5.1） |

### P2 —— 打磨与清理

12. **每个页面的副标题都是“你的信息，你来掌握。”**，顶部都有同一行小字 “A LITTLE SPACE, JUST FOR YOU”。重复后就成了噪音，建议每页写一句真正有用的说明（如“我的课表：这学期的 HKU 课程，按周查看”），或干脆去掉。**进展（2026-11-15）：已完成，各页副标题改为该页的实际用途，英文小标题只留在首页。**
13. **加载状态只有一行“正在读取…”**，换成骨架屏（灰色占位块）会显得更快、更稳。**进展（2026-11-15）：已完成，共用 `Skeleton` 组件（读屏只读出“正在读取…”文字，尊重“减少动态效果”）。**
14. **遗留代码**：首页已不显示天气，但 `GET /api/v1/discover/today` 和前端 `api.today` 仍在，可删掉以免误会。**进展（2026-11-15）：已删除该接口、`api.today` 及只供它使用的活动推荐；天气服务保留给 AI 助手的天气工具。**
15. **测试数据与隐私**：本地库里还有测试账号 `preview_guide_test`；课表教程第 1 张图里有你的真实姓名（会展示给所有用户），建议打码后替换。**进展（2026-11-15）：教程图已遮盖姓名；测试账号已删除。**
16. **CI 未配置**：文档要求“通过 CI 后合并”，但仓库没有 CI。代码进 Git 后，可用 GitHub Actions 跑 `scripts/check.sh`。
17. **HKU 指南现在只有 3 类**，内容质量高但量少；以后可按学生高频问题补（如“新生第一周 checklist”），继续坚持只用官方来源。

## 四、前端为什么“不够亮眼”

逐页看下来，原因很集中：

1. **只有一种颜色**：几乎所有元素都是浅绿 + 米白，缺少强调色。按钮、卡片、标签、空状态长得差不多，眼睛没有落点。
2. **对比度低、字太小**：大量 9–12px 的浅灰字，让页面显得“淡”。精致≠看不清。
3. **每页同一个模板**：返回按钮 → 英文小标题 → 大标题 → 同一句副标题 → 一张白卡片。功能各不相同，看起来却一模一样，缺少层次和个性。
4. **首页信息密度太低**：首屏只有问候语和一个对话框，下方大片留白（手机上尤其明显），最有价值的数据没上首屏。
5. **导航藏在汉堡菜单里**：桌面端有足够空间，却每次都要点开抽屉；手机上没有底部导航。
6. **缺少动效与质感**：只有很少的过渡动画；没有骨架屏、没有深色模式、没有插画或图标体系（除了图书馆 2.5D 图，这是目前最“亮眼”的部分，说明方向是对的）。
7. **样式难以统一调整**：`styles.css` 有 4700 多行，颜色和字号都直接写死，没有设计变量，所以每改一处风格都要到处找。

## 五、前端优化方案

### 第 1 步：先打地基（约 1–2 天，改动面广但风险低）

- **设计变量**：在 `:root` 定义颜色、字号、间距、圆角、阴影（如 `--color-text`、`--color-muted`、`--accent`、`--radius-lg`），把现有写死的值逐步替换。之后换主题、做深色模式都只改变量。
- **字号与对比度**：建立字号阶梯（12 / 13 / 14 / 16 / 20 / 28 / 40px），正文 14–15px；浅灰文字统一到对比度 ≥ 4.5。
- **一个品牌主色 + 一组功能色**：保留现在的深绿作为主色，加一个暖色强调（问候语旁边的珊瑚色 ✳ 就很好，可以用到主要按钮、今天标记、未读数上），并为四大功能各配一个辅助色：日程（绿）、邮箱（蓝）、课程翻译（紫）、HKU 指南（琥珀）。菜单图标、页面标题、卡片顶边都用对应颜色，用户一眼知道自己在哪个功能里。
- **深色模式**：跟随系统，晚上在宿舍看课表、在课室看字幕都更舒服。

### 第 2 步：重做首页（约 2–3 天，效果最明显）

做成**“今日看板”**（便当盒式网格）：

```
┌──────────────────────────────────────────────┐
│ 晚上好，Zongxi ✳     11月15日 周日 · 第 11 周   │
├───────────────────────┬──────────────────────┤
│ 下一节课               │ 今天的截止事项         │
│ COMP7607  19:00 LE1   │ ● Essay  还剩 5 小时   │
│ 还有 42 分钟 [去这里]   │ ● Quiz 2 明天 23:59    │
├───────────────────────┴──────────────────────┤
│ ✦ 问点什么…（AI 对话，做成显眼的输入条）          │
├──────────────┬──────────────┬────────────────┤
│ 3 封新邮件     │ 开始上课翻译   │ 添加日程         │
│ 已自动摘要     │ （上课时间高亮）│                 │
└──────────────┴──────────────┴────────────────┘
```

- 问候区按时间变化背景（早晨暖色、晚上深色渐变），配一个小插画或港大校园线稿。
- 数字和倒计时用等宽数字（`font-variant-numeric: tabular-nums`），跳动时不晃。

### 第 3 步：导航与页面骨架（约 1–2 天）

- **桌面端**（宽度 ≥ 1100px）：左侧常驻侧边栏，显示图标和名称，当前页高亮为对应功能色。
- **手机端**：底部 5 个标签（首页 / 日程 / 邮箱 / 翻译 / 指南），拇指可达。
- **页面头部**：去掉重复的英文小标题和统一副标题；换成“功能色图标 + 标题 + 一句有用的说明 + 右侧主要操作按钮”。

### 第 4 步：重点页面的“高光时刻”（每项约 0.5–1 天）

- **课程翻译**：开始上课后进入深色“课堂模式”，中英字幕大字号、全屏，当前句高亮；这是最能让同学“哇”一声的地方。
- **我的课表**：显示“第 n 周”、今天一列高亮、当前时间红线；课程卡片悬停显示课程全名和地点。
- **邮件通知**：按分类配色的标签（课程、行政、活动、可忽略），摘要第一句加粗。
- **HKU 指南**：每类配一张头图或图标；图书馆的 2.5D 风格可以延续到其他页面（例如交通页的港铁出口示意）。

### 第 5 步：动效与细节

- 骨架屏替代“正在读取…”；卡片进入时轻微上浮淡入；按钮按下有反馈。
- 尊重系统的“减少动态效果”设置（`prefers-reduced-motion`）。
- 空状态配简单插画和明确的下一步按钮。
- 做成可安装的手机应用（PWA：图标、启动页、离线显示课表），为提醒推送打基础。

> 以上都不需要新增前端依赖（React + CSS 即可完成）。若想用现成的组件库或图标库，属于新技术选型，按项目规则需先确认。

## 六、建议的执行顺序

1. **今天**：把代码提交进 Git（P0-1）。
2. **本周**：可读性与设计变量（P0-3 + 前端第 1 步）→ 首页今日看板（P1-5 + 前端第 2 步）。
3. **下周**：导航骨架（前端第 3 步）→ 学校邮箱转发说明（P0-2 短期方案）→ 课表与课程翻译打通（P1-7）。
4. **之后**：提醒（P1-6）、账号功能（P1-10）、课堂模式与课表细节（前端第 4 步）；交付方式（P0-4）和 Outlook 接入单独讨论确认。
