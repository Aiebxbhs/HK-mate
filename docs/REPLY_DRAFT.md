# 回复草稿与起草新邮件（本地 Qwen）

第一阶段只起草，不发送。HK Mate 仍然只有 Gmail `gmail.readonly` 权限，不能发送、保存草稿或修改邮件。

## 使用

- 统一收件箱：三栏布局，左侧邮件列表、中间原邮件、右侧“AI 助手”（上方邮件摘要，下方回复草稿表单，默认展开）。窄屏时 AI 助手排在原邮件下方，手机上依次为原邮件、AI 助手、邮件列表。
- 首页新邮件通知：点卡片上的“起草回复”，在弹窗中操作。

选择回复意图（同意 / 婉拒 / 询问细节 / 约时间 / 致谢 / 自己写要点），可补充说明，选择语气（正式 / 友好）、语言（跟随原邮件 / 中文 / English）和署名（只保存在本机浏览器中）。生成后草稿可直接编辑，可“重新生成”“复制草稿”或“在 Gmail 中打开”。后者打开 Gmail 写信页面并预填收件人、主题和正文，由用户在 Gmail 中检查后自行发送；新窗口不在原邮件会话串中。

菜单“我的邮箱”下有统一收件箱、起草邮件和邮箱管理三项。“起草邮件”用于写一封新邮件：填写收件人称呼（可选，会发给模型）、收件人邮箱（可选，只用于“在 Gmail 中打开”，不发给模型）、想写的内容和要点、语气、语言和署名，生成可编辑的主题与正文，可分别复制或在 Gmail 中打开（发件邮箱从已连接的 Gmail 中选择）。

## 实现

- 接口：`POST /api/v1/email-connections/{connection_id}/messages/{message_id}/reply-draft`，请求体只接受 `intent`、`note`（≤500 字）、`tone`、`language`、`signature`（≤60 字），不接受收件人或正文。受登录、Origin、CSRF 和邮箱归属校验保护；后端自行读取原邮件。
- 模型：与摘要相同的本机 Ollama + `qwen3:4b-instruct-2507-q4_K_M`，共用模型锁（忙时 503），无工具，不调用云模型。`temperature` 0.5，重新生成会得到不同措辞。提示词在 `backend/app/mail_reply.py`（`reply-draft-v2`）。
- 起草新邮件：`POST /api/v1/compose-draft`，请求体只接受 `purpose`（≤1000 字）、`recipient`（≤100 字）、`tone`、`language`、`signature`，需要登录与 CSRF，共用模型锁，不读取任何邮箱。提示词为 `compose-draft-v3`（输入含今天的香港日期，避免把未来日期误报为笔误），主题去掉 Re/Fwd 前缀。首页 AI 助手的 `draft_email` 工具也调用同一函数（见 `docs/AI_AGENT_PLAN.md` 第 13 节）。
- 敏感信息兜底：用户输入中“password / 密码 / 验证码”等词后带明确分隔符或数字的内容，若出现在生成的主题、正文或核对清单中，由程序替换为【已移除：敏感信息】并提示用户；回复草稿的补充说明同样适用。合成试跑中模型曾无视提示词把密码写进正文，因此不依赖提示词。
- 草稿和邮件内容不写入数据库、不记录日志。收件人取原邮件发件人，主题为 `Re: 原主题`（已有 Re/回复 前缀时不重复）。
- 模型只写称呼、正文和结束语；署名由程序追加（未填写时为【需补充：署名】），并删除模型在结束语后自行编写的落款。`[Your Name]`、`[time]` 等方括号占位会转换为【需补充：…】，前端会统计并提醒尚未补充的位置。

## 已知限制

- 小模型可能措辞生硬或遗漏细节，发送前必须逐句核对；缺少的具体信息应显示为占位，但不能保证模型从不编造。
- 在 Gmail 中发送时，发件人是该 Gmail 地址。从学校邮箱自动转发来的邮件，回复也会从 Gmail 地址发出。
- 手动转发（主题以 FW/Fwd 开头）的邮件，发件人通常是转发者本人，草稿的收件人也会是转发者，需在 Gmail 中改为真正的收件人。
- 系统内发送（需要 `gmail.send` 权限并重新授权）尚未实现，实施前需另行确认。

## 合成邮件试跑（2026-11-13）

6 封合成邮件（同意并给定时间、询问细节、中文婉拒、提示注入、未填署名、自写要点），单次运行：v1 出现忽略署名、写 `[Your Name]`、在结束语后编写“A student”等问题，v2 改由程序处理署名和占位后均正确；全部未编造具体时间，注入邮件未泄露密码。每封约 1–4 秒（模型已加载）。样本很小，不代表语义质量评估。
