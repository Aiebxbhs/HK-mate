# 自动新邮件通知与摘要

默认随 FastAPI 启动，当前只支持单后端进程。运行 `bash scripts/dev.sh` 和 `bash scripts/ollama-serve.sh`，在网页连接 Gmail 后即可使用。无需学校 Microsoft Graph 权限；学校转发规则须先让 Gmail 真正收到邮件。

## 行为

- 网易邮箱（163 / 126 / yeah.net）也在后台检测，约每 60 秒一次，见 `docs/NETEASE_MAIL.md`；下面的 historyId、补查等细节只针对 Gmail。

- 后台检测线程约每 15 秒检查已连接的 Gmail；生成线程独立工作，不因正在生成摘要而停止检测。页面约每 3 秒获取通知，收到新通知自动展开，无需手动生成。浏览器后台节流、网络、学校转发和模型加载均可能增加延迟，这不是公网推送。
- 通知在“邮件 → 统一收件箱”顶部（2026-11-15 由首页移来），导航“邮件”旁显示未处理数量；没有新邮件时隐藏整个通知模块，仍在后台检查。
- 系统通知（2026-11-16）：每封新邮件处理完后，后端在本机弹出一条 macOS 通知中心横幅（标题为发件人，副标题为主题，正文为摘要概述；摘要失败时提示到 HK Mate 查看），不需要打开网页。每封邮件只弹一次，重试不重复；只为在本机仍有有效登录的账号弹出，退出登录后不再显示该账号的邮件；上课实时翻译期间摘要排队，横幅随之延后。通过系统自带的 `osascript` 发出（`backend/app/system_notify.py`，不新增依赖），邮件文字只作为参数传入、不拼进脚本、不写日志。因此横幅在系统里归在“脚本编辑器”名下，点击横幅不会打开 HK Mate；若没有弹出，到“系统设置 → 通知 → 脚本编辑器”允许通知，并检查专注模式。打包成 App 后改为以 App 自身名义发出。`HKM_SYSTEM_NOTIFICATIONS=false` 可关闭；测试夹具默认关闭。非 macOS 系统不弹。
- 首次连接的检测器补查最近一小时。它先取得 Gmail historyId，再分页查该时间之后的已收邮件；不把所有未读邮件视为新邮件，不扫描更早历史。之后使用 `history.list` 的 messageAdded 增量；游标过期时从上次成功检查前一分钟补查并去重。
- 处理全部新来信，排除已发送、草稿、垃圾邮件和垃圾箱。当前历史页/补查页为 100 个记录，只有完成整页后才保存分页游标，最后一页才推进 historyId；失败后重读依靠唯一键去重。
- 新邮件先显示排队/生成中，再展示本地 Qwen 生成的自然语言摘要与分类。模型先写摘要、再根据邮件内容和摘要选类别（同一次调用，JSON 字段顺序保证）。
- 分类（2026-11-15）：学校邮件、求职邮件、账单与账户、广告推广，分不进的为其他邮件；它是模型判断，不代表发件人真实性验证，邮件中要求改分类的文字一律忽略。旧通知里的旧类别读取时自动换算（课程作业发布 / 学校通知 → 学校邮件，广告推荐 → 广告推广，会议安排 → 其他邮件），随后由补分类重新判定。
- 补分类：检测线程每 10 分钟为每个邮箱列出最近 10 天的已收邮件（不含已发送、草稿、垃圾箱，最多 3 页 × 100 封）以及所有未忽略的旧通知，没有类别的排入队列；生成线程在没有待摘要的新邮件时，按从新到旧逐封读取正文、用单独的轻量提示（一句话概括 + 类别，概括不保存）分类。上课实时翻译期间与摘要一样暂停。失败的条目 1 小时后由下一次扫描重试，Gmail 中已删除的邮件直接移除。新邮件摘要和收件箱手动摘要完成时直接写入类别，不再重复分类。统一收件箱每封邮件显示类别标签，排队中显示“分类中”，超出 10 天且未分类的邮件不显示标签。合成邮件实测（15 封，覆盖五类与“学校转发招聘”“邮件内要求改分类”两种情况）全部正确，单封约 0.7 秒。
- 模型与手动摘要共用单一互斥锁，自动串行生成。失败会显示原因，用户可重试，不使用示例或云模型补救。重启时将未完成任务重新入队；已完成任务不会再次生成。
- 忽略只在本系统持久化隐藏通知，不标已读、不删除、不移动 Gmail 邮件，也不会因刷新再次出现。查看原邮件读取真实纯文本；“加入日程”打开与“我的日程”相同的空白添加表单，不从邮件自动填写内容，由用户自行填写标题、日期、时间和地点；保存后首页与“我的日程”自动刷新。
- 页面离开或浏览器关闭后，只要后端与 Ollama 仍运行，后台继续处理；本地后端停止时不检测，重启后从已保存游标续接。可用 `HKM_AUTO_MAIL_ENABLED=false` 关闭后台功能；测试夹具默认关闭，避免访问真实邮箱。

## 数据与权限

新增 `mail_watches` 与 `mail_notifications`，迁移前已做私有数据库备份。`mail_categories`（迁移 e8b4c2d7f6a1，2026-11-15 经用户同意新增）每封邮件一行，只存账号、邮箱连接、Gmail messageId、类别、状态与时间，不存主题、正文或摘要；按账号隔离，解绑邮箱时级联删除。检测状态、邮件主题/发件人/摘要/证据片段使用现有 Fernet 密钥加密，不存完整正文、不打印邮件或模型文本。唯一键为邮箱连接 + Gmail messageId，不能通过反复刷新重复生成。

通知关联 user_id 和 connection_id。API 从服务端登录会话确定用户，拒绝跨账号查看、忽略和重试；写操作验证 Origin 和 CSRF。邮箱解绑完成时级联删除游标和通知，待解绑或重新授权期间停止读取并隐藏该连接通知。忽略中的推理结果、解绑后迟到的结果不会重新创建通知。

## 接口

- `GET /api/v1/mail-notifications`：当前用户所有未忽略通知，含状态、摘要、类别（`category`，已存类别优先于摘要中的类别）、检测错误和最近成功检查时间。
- `GET /api/v1/messages`：每封邮件附 `category` 与 `category_status`（`done` / `pending` / 无）。每页 100 条，`next_cursor` 为下一页游标，游标也验证归属；页面会自动加载全部页。
- `POST /api/v1/mail-notifications/check`：唤醒检测线程，不同步等待模型。
- `POST /api/v1/mail-notifications/{id}/dismiss`：仅隐藏该通知。
- `POST /api/v1/mail-notifications/{id}/retry`：仅将未忽略的失败任务重新入队。

开发验证使用合成邮件，覆盖新信检测、历史排除、增量重复、分页游标、模型失败重试、重启恢复、加密存储、跨用户及解绑清理。人工联调：保持首页打开，发送一封新的合成测试邮件到学校邮箱，确认 Gmail 收到后观察通知由排队转为摘要与分类。
